# Rotterdam Breast-Cancer Experiment

Real-data comparison of the partially linear **FLEXI-Haz** model and the
proportional-hazards DNN of **Zhong, Mueller & Wang (2022)** on the
Rotterdam breast-cancer data. Both models estimate the treatment
coefficients `theta` of hormonal therapy and chemotherapy, with standard
errors and confidence intervals, while the clinical covariates enter
through a neural network. Both are fitted with the same class,
`flexihaz.FlexiHazardModel`, selected by `model_type="flexihaz"` or
`model_type="zhong"`, so the data handling, folds, tuning grid, restarts
and inference code are identical.

## Files

``` text
rotterdam_breast_cancer.csv   the data (2,982 patients)
rotterdam_io.py               endpoint, covariate design, outer folds, JSON helpers
run_rotterdam_grid_cv.py      the experiment: per-fold architecture grid, restarts, theta inference
```

Nothing else is needed. Outputs are written under `results/` (ignored by
git) and are regenerated by the runner.

## Dataset and endpoint

Time from primary surgery to the first of recurrence and death; the event
indicator is 1 only when that first observed time is an event (44.0% censoring):

``` python
T = np.minimum(rtime, dtime)
delta = ((recur == 1) & (rtime <= dtime)) | ((death == 1) & (dtime <= rtime))
```

`pid` and `year` are not used.

## Covariates

Flexible covariates `X` (network input):

``` text
age, nodes, pgr, er, meno, grade, tumor size (one-hot: size_<=20, size_20-50, size_>50)
```

Linear treatment covariates `Z`, by design:

| `--design`       | `Z`                                                              |
|------------------|------------------------------------------------------------------|
| `standard`       | `chemo`, `hormon`                                                |
| `er_interaction` | `hormon_low_er`, `hormon_high_er`, `chemo_low_er`, `chemo_high_er` |

In the ER-interaction design each treatment indicator is split at
`ER = 61` (the sample median): `hormon_low_er = hormon * I(er < 61)`,
`hormon_high_er = hormon * I(er >= 61)`, and likewise for `chemo`. `X`
and `Z` are standardized inside the model on the training rows; `theta`
and its covariance are reported on the original scale.

## Models

| `--model-type` | hazard                                   | fitting                                            | variance of `theta`                                           |
|----------------|-------------------------------------------|----------------------------------------------------|---------------------------------------------------------------|
| `flexihaz`     | `h(t|X,Z) = exp{theta'Z + g(t,X)}`        | piecewise-exponential (Poisson) likelihood, `grid_size="n"`, mini-batch Adam | cross-fitted residual nets `Z - E[Z|X,t]` with one joint `(t, X)` network |
| `zhong`        | `h(t|X,Z) = h0(t) exp{theta'Z + g(X)}`    | Breslow partial likelihood, one full-batch Adam step per epoch | same construction with the additive network `g_X(X) + g_T(t)` of Zhong et al. (no `X`-`t` interaction) |

Both use ReLU networks, no dropout, no weight decay, early stopping on
an internal 67%/33% subject split, a Cox (X+Z) warm start of `theta`,
and `K` random restarts (default 5) of which the one with the lowest
validation loss is kept.

Two training options matter for the comparison:

- **Learning-rate multiplier for `theta`** (`--theta-lr-mult M`,
  `FlexiHazardModel(theta_lr_multiplier=M)`): the linear branch is
  trained with `M` times the network learning rate (a separate Adam
  parameter group). With `M = 1` the small fixed learning rate used for
  the network also governs `theta`, and early stopping can halt before
  `theta` has moved far from its warm start; `M = 20` is the value used
  for FLEXI-Haz in our runs. It applies only to the linear branch and
  leaves the network's rate unchanged.
- **Learning-rate schedule and refinement**: by default both models use
  the three-phase warm-started schedule `lr, lr/10, lr/100` (each phase
  with its own early stopping) and, after training, an exact
  profile-likelihood re-solve of `theta` with the network held fixed
  (`refine_theta`). `--zhong-plain` switches both off, which is Zhong's
  own recipe (one constant-rate phase, `theta` = the jointly trained
  coefficient). `--no-three-phase-lr` and `--no-refine-theta` control
  them separately for either model.

## Protocol

1. **Outer folds.** Five folds (`KFold`, shuffled, `random_state=--seed`),
   stored in `results/folds_seed<seed>.csv`. `--seed` also seeds the
   network initialisation (`seed + fold`) and the restarts. Each fold's
   model is fitted on the other four folds' rows only. Our runs used seed
   **20260303** for FLEXI-Haz and **20260707** for Zhong; the comparison
   table in the report pairs those two runs.
2. **Grid, per fold.** Depth `L in {2, 3, 4, 5, 6}` times width
   `w in {25, 50, 100, 150, 200, 300, 500}`: 35 architectures
   `hidden_layers = (w,) * L`, weight decay 0, dropout 0. FLEXI-Haz searches
   the architecture only, at the fixed learning rate `1e-3`. Zhong searches
   architecture x learning rate over `{1e-5, 5e-5, 1e-4, 5e-4, 1e-3, 5e-3, 1e-2}`
   (245 fits per fold), since Zhong et al. tune both. Each candidate is
   trained once and scored by its validation loss on the internal 67/33
   split; the smallest loss wins. `--learning-rates` overrides the grid.
3. **Final fit.** The selected architecture is refitted with `K`
   restarts; the lowest-validation-loss restart is kept.
4. **Inference.** `theta`, its standard error, 90% and 95% normal
   confidence intervals and hazard ratios per fold; across folds the
   mean estimate, the standard deviation of the fold estimates, the mean
   standard error and the mean confidence-interval bounds.

Both models use at most 500 epochs per learning-rate phase and patience 30
(`--max-epochs`, `--patience`), as in setting 1.

## Running

Install the package from the repository root (`pip install -e .`;
`lifelines` is required for the Cox warm start and is in
`requirements.txt`). Then, from this directory:

``` bash
# FLEXI-Haz, both designs, theta learning rate x20, seed 20260303
python run_rotterdam_grid_cv.py --model-type flexihaz --design er_interaction --theta-lr-mult 20 --seed 20260303
python run_rotterdam_grid_cv.py --model-type flexihaz --design standard       --theta-lr-mult 20 --seed 20260303

# Zhong et al. (2022), Zhong's own recipe, both designs, seed 20260707
python run_rotterdam_grid_cv.py --model-type zhong --design er_interaction --zhong-plain --seed 20260707
python run_rotterdam_grid_cv.py --model-type zhong --design standard       --zhong-plain --seed 20260707
```

Useful options: `--start-fold/--end-fold` to split folds across
machines, `--layers`/`--widths`/`--learning-rates` to change the grid,
`--n-restarts`, `--restart-selection {val_loss,efficient_score}`,
`--skip-completed` to resume, `--smoke-test` for a 1-minute check.
`python run_rotterdam_grid_cv.py --help` lists everything.

## Outputs

`results/<model_type>_gridcv[_thetalr<M>][_plain]/<design>_seed<seed>/`:

``` text
fold_XX_grid.csv               validation loss, epochs and time of every (architecture, lr) candidate
fold_XX_treatment_effects.csv  theta, se, ci90, ci95, hazard ratio of the selected architecture
fold_XX_log.json               selected architecture and learning rate, restarts (seed, val loss, theta), timings
summary_treatment_effects.csv  across-fold mean estimate, sd, mean se, mean CIs, significance
```

plus `results/folds_seed<seed>.csv` and `results/data_metadata.json` at the
top level. All of it is regenerated by the runner and not committed.
